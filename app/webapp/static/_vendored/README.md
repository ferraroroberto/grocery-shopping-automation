# `_vendored/` — fleet web-app component library

Byte-copyable UI components shared across every fleet web app (FastAPI + static PWA). This is the **UI-layer** counterpart to the tray's vendored primitive (`app/tray/single_instance.py`) and the shared `tray_lifecycle.ps1` helper: the same "copy verbatim, never fork per-app" channel, for HTML/CSS/JS.

## The split (single-home-by-altitude)

- **`fleet-config`** owns the *spec*: `design.md` + `design.dark.md` (the agent-readable visual identity + navigation contract, junctioned into `~/.claude`) and the `/design-sync` skill. The rules.
- **`project-scaffolding`** (here) owns the *implementation*: the actual HTML/CSS/JS snippets an app copies verbatim. The code.

A cloned web app inherits both: design **tokens** (wire your CSS custom properties to `~/.claude/design.md`) and **components** (vendor from here). It re-authors neither.

[`demo.html`](demo.html) is the component gallery: open it over HTTP to eyeball every component in light + dark; `tests/e2e/test_vendored_components.py` drives the same page and asserts each component's key computed styles in both themes._

## Adding a new vendored component

1. **Normalize** it from the best existing implementation in the fleet (don't invent a fresh one — pick the cleanest real usage and generalize it: discover from the DOM instead of hardcoding, take per-app values as parameters, depend only on design tokens).
2. Create `_vendored/<component>/` with the asset files + a `README.md` listing its files, the copy-verbatim recipe, the markup contract, and the **required design tokens** (referenced, never redefined).
3. Reference `~/.claude/design.md` for tokens; never copy the spec into the component.
4. Add a row to the table above and re-skin the source app to consume the vendored copy (tracked as a separate issue, not bundled here).

## Rules

- **Vendor verbatim.** Don't edit a component's shipped files per-app. Per-app variation is *markup* and *token values* only. To change a component, change it here and re-vendor downstream.
- **Tokens, not hardcoded values.** Components reference design-system CSS custom properties so one spec drives every app's look.
- **A component owns its controls' typeface.** Every component stylesheet that styles a `<button>`, `<input>`, `<select>` or `<textarea>` its markup renders sets `font: inherit; line-height: normal;` on that control's own class, before its `font-size`/`font-weight` (the shorthand resets both), so the control is correct whether or not the app vendors `base/`. Never lean on an element selector from another file, and never use the bare shorthand without `line-height: normal` (it inherits the body's 1.5 and grows every padded control). `base/` stays as the app-level safety net for bare controls. A component that renders no control (`card`, `disclosure`, `icon-tile`, `page-foot`, `toast`; `text-size` reuses `segmented`) needs nothing. Pinned by `tests/e2e/test_vendored_font_inherit.py`, which loads the gallery and the nav with `base.css` removed. (`#319`, `fleet-config#1211`.)
- **Web-app shape only.** This is FastAPI + static PWA guidance. Streamlit POC spikes are exempt.
- **Propagation freeze.** A vendored-component fix (here, or the tray primitive `app/tray/single_instance.py`) does not fan out to sister repos until this scaffold's own gate — including any behavioral harness for that component — is green. A **second** bug in the same component within the **same day** freezes propagation entirely: harden and soak at source, ship one cumulative wave, never a rushed second patch mid-cascade. (`project-scaffolding#152`, motivated by the 2026-07-09/10 tray cascade, #144→#150.)
- **Propagation trigger.** Once a vendored component changes here and the gate is green, propagation to sister repos happens via one `/propagate-vendored` run from `fleet-config` (`ferraroroberto/fleet-config#338`), batched across every affected repo in a single pass — never a hand-filed per-repo issue per fix. The skill and its version-manifest logic live in `fleet-config`; this repo only carries the trigger note.
- **The channel rule — "does it ship with the app?"** (`project-scaffolding#153`.) Three distribution channels, picked by what the thing *is*, not by convenience: **app-shipped assets** (this directory's UI components, and `app/tray/single_instance.py` — imported code that runs *inside* each app's own process) → **vendored** here, propagated per-repo via manifest + `/propagate-vendored`; **machine-local infrastructure** (a helper every app on this one machine shells out to by path, never imported, never shipped elsewhere — `tray_lifecycle.ps1` is the first instance) → **one shared, junctioned copy owned by `fleet-config`** (`~/.claude/tray/`, `install.ps1`), never vendored per-repo; **specs/conventions** (design tokens, workflow rules) → live once at `CLAUDE.md`/`design.md` altitude, never copied anywhere. `tray_lifecycle.ps1` moved from this directory's sibling `app/tray/` to the fleet-config channel in `project-scaffolding#153` — it never shipped *with* an app, every copy ran on the same one Windows box, so vendoring it bought per-app version pinning nobody used at 6-7x the propagation labor.
